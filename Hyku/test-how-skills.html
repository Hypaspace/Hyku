S-01 Instruction folders A skill is a folder containing a SKILL.md file plus any supporting scripts, data, or references. Claude reads these at session start and uses them as specialised knowledge for specific tasks.
S-02 Auto-activation You don't invoke most skills by name. Claude reads all installed SKILL.md files and activates the right one based on your request. Ask it to build a landing page and the frontend skill fires. Ask for an audit and the right commands are reached for.
S-03 Lightweight Skills load ~100 tokens at session start — far less than an equivalent MCP server. Multiple skills can be active simultaneously without significant performance impact. Prefer skills over MCP where both could solve the problem.
S-04 Anyone can write one A skill is just markdown. Repeating the same context, preferences, or instructions across sessions? Those belong in a skill. Encode your design system, component patterns, team conventions — available in every session.
S-05 Skills vs prompts vs MCP Prompts are one-shot. Skills persist across sessions, activate by context. MCP servers give live tool access (APIs, databases) but consume more tokens. Use skills for reusable expertise; MCP for live data.
S-06 Claude Code only Skills require the terminal-based agent, not claude.ai. If using the web UI, equivalent is uploading reference documents or writing a system prompt. Install via npm install -g @anthropic-ai/claude-code.

STEP 01 · INSTALL
Skills are instruction folders
A skill is a folder containing a SKILL.md file. Drop it in ~/.claude/skills/ globally or .claude/skills/ per project.
STEP 02 · LOAD
Session-start injection
Claude reads all SKILL.md files at session start. Each skill costs ~100 tokens — multiple can be active simultaneously without meaningful performance loss.
STEP 03 · MATCH
Automatic activation
Skills activate based on context, not explicit invocation. Ask to build a landing page and the frontend skill fires. Ask for an audit and the right tool is reached for.
STEP 04 · EXECUTE
Specialised output
The active skill shapes how Claude responds — applying your encoded conventions, design system, and preferences to every output. Override by calling /command directly.
AUTHORING
Anyone can write one
A skill is just markdown. Encode your design system, component patterns, team conventions — they'll be available in every session without re-explaining. No build step required.
COMPARISON
Skills vs prompts vs MCP
Prompts are one-shot — you rewrite them each time. Skills persist across sessions, activate by context. MCP servers give live tool access but consume far more tokens. Use skills for reusable expertise; MCP only for live data that genuinely needs an API.
